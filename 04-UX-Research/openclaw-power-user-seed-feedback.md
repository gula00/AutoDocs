# 种子用户体验反馈报告：CoworkDesk（OpenClaw 重度用户视角）

## 评测结论（一句话）

这是一个“有 Agent 雏形、透明度做对了一半”的桌面端，但离 OpenClaw power user 的生产级标准还差关键两步：可控等待反馈和可观测成本/会话管理。

## 总体评分（10分制）

**6.9 / 10**

| 维度 | 评分 | 说明 |
|---|---:|---|
| 首次进入与信息架构可理解性 | 7.2 | 首页结构清楚（Workspace / Metrics / Environment），但操作入口不够聚焦 |
| 核心对话/协作流程流畅度 | 6.3 | 能完成任务，但出现“Sending request 长时间无进度解释” |
| Agent 透明度（可见/可控/可追溯） | 8.4 | `execXXms` 可展开看输入输出，方向正确 |
| 多模型支持与切换体验 | 7.0 | Provider 覆盖广，但会话中切换反馈不直观、入口可发现性一般 |
| 数据主权与隐私感知 | 7.6 | 本地工作区、Keychain、`~/.openclaw` 导入加分；遥测/数据外发边界未显式说明 |

## 关键亮点（3-5条）

- Agent 透明度有基础：工具调用以 `exec57ms` 形式内联，且可展开看到 `Input/Output`，这点比很多“只会聊天”的壳子强。
- 本地主权信号明确：界面直接展示 `~/.openclaw/workspace`、File Watcher、Gateway 状态，符合 OpenClaw 用户心智。
- 模型配置不是玩具：在“Models & API”可看到 Anthropic/OpenAI/智谱/DeepSeek/Gemini/Ollama/自定义 provider。
- 出错信息可读：执行不存在命令能返回 `command not found` + `exit code 127`，对工程用户友好。
- 视觉基调正确：真暗背景+高信息密度侧栏，具备长时间使用潜力。

## 关键问题（按严重级别）

### P0（致命）

1) 请求进入“Sending request...”长时间无进展，用户无法判断是卡住还是正在执行

- 复现路径：输入“请帮我列出当前工作区根目录文件…”后发送，界面停留在 `Sending request... / Awaiting task initialization...`。
- 影响：这是核心链路黑洞，直接击穿“可控性”和“信任感”；power user 会怀疑网关挂了或队列阻塞。
- 现象 -> 根因假设 -> 建议方案：
  - 现象：无阶段性反馈，仅一个静态等待文案。
  - 根因假设：网关握手/agent plan/build 阶段没有状态事件上报到 UI。
  - 建议：把链路拆成阶段状态机并可视化（Queued / Planning / Tool call / Streaming / Done），每阶段给耗时与可取消动作。

### P1（严重）

2) Token/成本指标始终为 0，成本可观测性失效

- 复现路径：完成两轮执行（含成功和错误命令）后，Session Metrics 仍显示 Tokens 0 / Est. Cost $0.000。
- 影响：24/7 用户无法做成本治理，ClawRouter/Manifest 用户会直接降级该工具优先级。
- 现象 -> 根因假设 -> 建议方案：
  - 现象：有指标框但无真实数据。
  - 根因假设：provider usage 字段未回填或聚合器未接入。
  - 建议：优先接通 per-turn usage，至少展示 `prompt/completion/total tokens` + 估算单价来源。

3) 会话生产力能力薄弱（看不到清晰会话列表/检索/导出）

- 复现路径：连续对话后仅看到单线程内容区，未发现历史检索与结构化导出入口。
- 影响：无法做长期知识沉淀，不符合“对话即工作产物”的真实使用场景。
- 现象 -> 根因假设 -> 建议方案：
  - 现象：主界面偏单会话，历史管理弱。
  - 根因假设：信息架构偏“实时执行器”而非“工作空间”。
  - 建议：补左侧 Session Rail（命名/搜索/固定/归档）+ 导出 JSON/Markdown。

### P2（中等）

4) 部分关键控件语义不清（无标签 icon button），可发现性与可访问性受损

- 复现路径：snapshot 中出现多个无文本按钮；需要尝试点击后才知道功能（如 copy）。
- 影响：新用户学习成本高，键盘/读屏器体验弱。
- 现象 -> 根因假设 -> 建议方案：
  - 现象：按钮无可读 label。
  - 根因假设：仅视觉图标，缺 aria/tooltip。
  - 建议：所有 icon button 增加 tooltip + aria-label + 快捷键提示。

5) 模型切换入口存在但会话内切换反馈不强

- 复现路径：顶部有 `GLM-4.7▼`，但会话中切换状态与生效时机不够清楚。
- 影响：多模型用户无法“低摩擦切脑”。
- 建议：切换后在输入框上方给一次性 toast + 当前回合模型徽标变化。

6) 设置层级交互有阻塞感（Add Model 弹层会挡住上层导航）

- 复现路径：打开“添加模型”后，切换上层 tab 受阻，需要先取消弹层。
- 影响：配置流程割裂，降低设置效率。
- 建议：统一为分步抽屉，避免双层 modal 叠加。

## “像 OpenClaw power user 一样”最在意的改进建议（优先级）

1. 先把等待透明做成产品能力，不是加载动画
   - 落地：增加 Agent Timeline（阶段、tool、耗时、状态），支持“停止/重试/继续”。
2. 把成本可观测打通到每条消息
   - 落地：消息级 token + 会话总览 + provider 估算单价；异常时显示“usage unavailable”而不是 0。
3. 补齐会话工作流：列表、搜索、分支、导出
   - 落地：Session Rail + `Cmd+N` 新建、`Cmd+K` 搜索/命令、导出 JSON/MD。
4. 强化数据主权可验证性
   - 落地：设置页新增“Data & Privacy”卡：本地存储路径、遥测开关、网络外发清单、一键清除与备份。
5. 提升键盘流与可发现性
   - 落地：`Cmd+/` 快捷键面板，所有高频操作可键盘完成；icon 按钮统一 tooltip。

## 2周改进冲刺建议

### Week 1（稳定性 + 透明度）

- 建立请求状态机并接 UI：Queued/Planning/Executing/Streaming/Done/Failed。
- 每次 tool call 显示开始时间、耗时、结果码；失败给可执行建议。
- 接通 usage 数据链路，至少完成“消息级 token + 会话累计”。
- 修复无标签按钮，补齐 tooltip/aria-label。

### Week 2（效率 + 主权 + 工作流）

- 上线 Session Rail：新建、重命名、搜索、归档、删除确认。
- 导出/导入：Markdown + JSON（最小可用）。
- 快捷键体系：`Cmd+N`、`Cmd+K`、`Cmd+,`、`Esc`、`Cmd+/`。
- Data & Privacy 面板：本地路径、遥测开关、离线模式说明、凭证存储说明（Keychain）。

## 最小可行验收指标（可量化）

- 等待透明度：95% 请求在 300ms 内出现阶段状态；“仅显示 Sending request 无后续状态”的比例 < 1%。
- 可控性：Stop 按钮可用率 99%，点击后 500ms 内进入已停止状态。
- 成本可观测：90% 以上消息显示 tokens；会话总量与消息求和误差 < 2%。
- 效率：核心操作（新建会话、切模型、开设置、搜索）100% 支持快捷键；快捷键发现入口点击率 > 30%。
- 会话管理：20+ 会话下检索首屏时间 < 200ms。
- 稳定性：连续 50 次请求无卡死；崩溃率 < 0.5%。
- 主权感知：设置页可直接看到数据路径与外发策略，用户完成“备份导出”路径 <= 3 步。

## 最终总结

这版 CoworkDesk 已经有 OpenClaw 用户会认可的核心气质：本地工作区、Agent执行、可展开工具轨迹、深色高密界面。问题在于它还没从“能跑”跨到“可托付”：等待阶段仍偏黑箱、成本指标不可用、会话资产化能力不足。只要按上面的两周冲刺把透明度 + 成本 + 会话工作流补齐，它就有机会从“尝鲜工具”进入 power user 的常驻工作台。
