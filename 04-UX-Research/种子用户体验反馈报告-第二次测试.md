# 种子用户体验反馈报告（第二次测试）

**测试时间**：2026年2月21日  
**署名**：opus 4.6  
**测试方式**：通过 CDP 远程调试连接 Electron 应用实际操作 + 源码审计  
**应用版本**：CoworkDesk (Electron 33.4.11 / Node v18.17.0)  
**测试环境**：macOS, Gateway 已连接 (ws://127.0.0.1:18789)

---

## 总体评分：6.0/10

CoworkDesk 已经从概念原型进化成了有骨架的产品。视觉设计有品味（5 套主题、真黑 OLED 背景、语义化配色），Agent 透明度有基本框架（tool call 展开/折叠、耗时显示），Gateway + OpenClaw 集成是真正的差异化。但作为一个每天在 Cursor + Claude Desktop + Open WebUI 之间切换的 power user，这款应用离我愿意把它固定在 Dock 上还有明显距离 -- Token 指标硬编码为 0、设置中声称的 Keychain 存储实际是明文 JSON、Terminal 面板是空壳、缺少 Cmd+K 命令面板和会话搜索，更严重的是 **测试过程中主进程 console.log 触发了 EPIPE 未捕获异常，直接弹出了错误弹窗**。它有好底子，但还需要把"看起来有"变成"真的能用"。

## 关键发现

### 发现 1: EPIPE 未捕获异常导致错误弹窗（P0-NEW）

测试过程中 Electron 弹出了 `Uncaught Exception: Error: write EPIPE` 的系统错误弹窗。

```
Uncaught Exception:
Error: write EPIPE
  at afterWriteDispatched (node:internal/stream_base_commons:161:15)
  at writeGeneric (node:internal/stream_base_commons:152:3)
  at Socket._writeGeneric (node:net:958:11)
  at Socket._write (node:net:970:8)
  at writeOrBuffer (node:internal/streams/writable:572:12)
  at _write (node:internal/streams/writable:501:10)
  at Writable.write (node:internal/streams/writable:510:10)
  at console.value (node:internal/console/constructor:303:16)
  at console.log (node:internal/console/constructor:378:26)
  at debugEventSummary (/Users/.../out/main/index.js:646:15)
```

**根因**: `src/main/gateway/client.ts:906` 的 `console.log()` —— 当 Electron 打包后 stdout 无 tty 或管道断开时，`console.log` 写入会抛出 EPIPE。该文件共有 4 处 `console.log`（行 112、331、906、1179），均存在此风险。错误没有被 try-catch 或 `process.on('uncaughtException')` 捕获，直接触发了 Electron 的默认错误弹窗。

**用户看到了一个满是堆栈信息的弹窗，这对信任是毁灭性的。**

### 发现 2: 安全声明与实际不符（P0）

UI 告诉用户 API Key "stored securely in macOS Keychain"，但实际是明文存在 `~/Library/Application Support/cowork-desk/settings.json`。用户宁愿你诚实说"存在本地文件"，也不要虚假的安全承诺。

### 发现 3: Token 追踪完全失效（P0）

Session Metrics 的 Tokens/Cost 永远是 0。对 24/7 跑 Agent 的用户来说，这等于仪表盘全部归零的飞机。

### 发现 4: 视觉设计是真正的亮点

5 套主题的品质远超同类竞品，这是产品最能打的维度。

### 发现 5: 多处"有壳无魂"

Terminal 面板是占位符，Tool call 语义标签有代码无显示，Paperclip/Globe/Terminal 按钮有图标无功能，模型选择器不工作。看到精美按钮点了没反应，比按钮不存在更让人沮丧。

## 亮点列表

1. **主题系统出类拔萃** -- 5 套主题各有性格（Raycast 红、Dracula 紫、Neon Noir 蓝粉、Nord 冰蓝、Monokai 绿），每套 30+ CSS 变量覆盖完整语义，即时切换无闪烁。放在竞品里是第一梯队。

2. **OpenClaw 原生集成** -- `Import from ~/.openclaw` 一键导入、workspace 路径统一、Gateway 状态实时显示含 ping 延迟。对已有 OpenClaw 用户几乎零配置。

3. **关键快捷键到位** -- Cmd+, 设置、Cmd+N 新建会话、Escape 关闭模态框、Enter 发送 / Shift+Enter 换行，macOS 原生操作逻辑。

4. **Tool Call 设计思路正确** -- ToolCallBlock 有完整的图标/颜色/语义标签/耗时/状态/展开详情，`TOOL_META` 映射了 Read/Write/Bash/Grep/Glob/WebFetch/Task 等多种工具，只是数据还没完全打通。

5. **本地优先架构** -- 数据存 `~/.openclaw`，Gateway 连 localhost，无强制登录注册。

## 改进建议（按优先级排序）

### 优先级 1: 立即修复（本周内）

#### 1a. 修复 EPIPE 崩溃（半天）

`src/main/gateway/client.ts` 中有 4 处 `console.log`（行 112、331、906、1179），打包后 stdout 无 tty 时会 EPIPE。最简方案：

```typescript
// main 入口添加
process.stdout?.on?.('error', () => {})
process.stderr?.on?.('error', () => {})
```

更好的方案：引入 `electron-log`，全局替换 console.log。

#### 1b. 修正安全声明（半天）

要么真的用 `safeStorage.encryptString()`，要么把 UI 文案改为 "Your API key is stored locally on this device"。

#### 1c. 打通 Token 追踪（1-2天）

Session Metrics UI 骨架已经完善。从 Gateway WebSocket 响应解析 `usage` 字段更新 Zustand store 即可。

### 优先级 2: 核心可用性（1-2周）

- 修复模型选择器 + 添加更多 provider 预设
- 实现会话列表/切换 UI
- 激活 Tool Call 语义标签
- 添加消息编辑/重新生成

### 优先级 3: 差异化能力（2-4周）

- Cmd+K 命令面板
- Terminal 面板接入 xterm.js
- MCP 支持
- 文件附件/图片上传

## OpenClaw 重度用户最终裁决

**当前会日常使用吗？** 不会。还不够。

**要做到什么程度才能让我 Dock 上给它一个位置？**

1. **不崩溃** -- EPIPE 这种错误弹窗不能出现在用户面前
2. **Token 追踪必须工作** -- 这是我在 Open WebUI 和 Cherry Studio 里最想要但得不到的功能
3. **MCP + Skills 管理** -- 让 CoworkDesk 成为 OpenClaw 生态的控制中心而不是另一个 Chat UI

做到这三件事，CoworkDesk 就有了不可替代的独特价值。那时候我不但会装，还会在 Discord 和即刻推荐。
